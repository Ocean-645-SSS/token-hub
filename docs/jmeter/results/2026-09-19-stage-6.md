# 阶段 6 验收与压测记录

| 项目 | 实际记录 |
|---|---|
| 环境 | JDK 17、Spring Boot 3.3.13、MySQL 8.0.33（隔离临时容器）、Redis 7、RabbitMQ 3、Elasticsearch 8.19.21、本地固定响应 OpenAI-compatible mock。 |
| API 验收 | `GET /api/packages` 200；普通订单 `WAIT_PAY → PAID → COMPLETED`，Wallet 可用额度增加 1,000,000；受控模型调用返回 `usage.total_tokens=20`；`POST /ai/recommend` 使用 `GPT` 查询得到 2 个 ES 候选并返回 mock 推荐。 |
| 发现并修复 | 初次普通下单失败：MyBatis 将 `OrderStatus.WAIT_PAY` 写入整数列。已为状态码字段加 `@EnumValue`，修复后重新实测通过。 |
| JMeter 场景 | `normal-purchase`，10 线程、每线程 1 次循环；每线程依次创建普通订单并模拟支付。 |
| 原始结果 | `docs/jmeter/results/2026-09-20-normal-purchase-success.jtl`；HTML 报告：`docs/jmeter/results/2026-09-20-normal-purchase-success/index.html`。 |
| 指标 | 20 样本，观察窗口 4.455 秒，吞吐 4.49 samples/s，P95 39 ms，P99 139 ms，错误率 0%。 |
| 数据库写入 | 10 orders、1 token_wallet、10 token_ledger、20 local_message；钱包与账本在支付后的异步发放完成后核对。 |
| 失败记录 | 首次运行产生 20/20 失败（JWT 参数未注入）；原始文件与 HTML 报告保留在 `2026-09-20-normal-purchase.jtl` / `2026-09-20-normal-purchase/`，修正后重跑通过。 |
| 对比 | 未执行直接 MySQL 与 Redis + Lua + MQ 的负载对比；上述数据仅代表普通购买小样本，不构成性能容量结论。 |

可复跑入口为 `docs/jmeter/tokenhub-v1.jmx`。运行时通过 `-Jjwt=<access-token> -Jthreads=<n> -Jloops=<n>` 注入参数；失败、超时或未达目标的结果必须保留。
